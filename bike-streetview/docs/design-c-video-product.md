# 設計書C: 実写動画×速度連動プロダクト（ユーザー提供・案2）

作成日: 2026-07-13 ／ 想定担当: Claude Opus（設計・M1-M3）、人間（権利・事業判断）
位置づけ: 将来ユーザーへ提供する場合の唯一の法的にクリーンな路線。
Kinomap / FulGaz / Rouvy と同型のコンセプトであり、差別化と動画調達が事業の本体になる。

## 前提となる意思決定（人間が行う）

- コンテンツ戦略: (a) 自前撮影のみ（小規模・確実） / (b) ユーザー投稿モデル
  （スケールするが審査・権利処理が必要） / (c) 既存プラットフォームのAPI提携。
  **本設計書は (a) 自前撮影MVP → (b) へ拡張可能な構成**で書く
- 提供形態: まずWebアプリ（既存資産流用）。ネイティブ化は後続判断

## コア技術: 動画とGPSログの同期

撮影時に GoPro等 + GPSログ（GPX）を記録し、
「動画時刻 t ⇔ 走行距離 d」の対応表（sync.json）を作る。
走行時はユーザーの累積距離 d から t を引き、playbackRate で追従させる。
これは設計書Bの meta.json / HyperlapsePlayer と**同一のプレイヤー実装を共有できる**
（distanceToTime補間＋playbackRate制御＋ドリフト補正）。先にBを実装しておくと
Cのプレイヤー工数はほぼゼロになる。

---

## マイルストーン1: コンテンツ規格と変換パイプライン

1. 撮影規格を `docs/content-spec.md` に定義:
   - 映像: 4K/30fps以上、手ブレ補正ON、ハンドルバー固定、順光推奨
   - GPS: 1秒間隔GPX（GoPro内蔵GPS or サイコン）。動画とGPXの時刻同期方法
     （撮影開始時に画面へ時計を映す等）を規定
   - 信号待ち・停止区間の扱い: 編集でカットし、GPX側も距離基準で詰める
     （距離が単調増加になるよう正規化）
2. 変換スクリプト `tools/build-course.mjs`:
   - 入力: mp4 + GPX → 出力: HLS（複数ビットレート）+ sync.json + 標高/勾配
     （GPX標高 or Elevation API）+ サムネイル + コースメタ（名称・距離・獲得標高）
   - 停止区間検出（速度<2km/hが10秒以上）を警告として出力
3. サンプルコース1本を自前撮影して通す（E2E検証）

受け入れ: 撮影→コマンド1発→配信可能なコースパッケージが完成する。

## マイルストーン2: プレイヤーとアプリ統合

1. 設計書Bの `HyperlapsePlayer` を `CoursePlayer` へ一般化
   （HLS再生: hls.js、sync.json補間、playbackRate追従、ドリフトseek）
2. 既存アプリの走行画面へ「コース走行モード」を追加:
   HUD（速度・距離・勾配・RPM）、ミニマップ（GPX由来polyline）、
   進捗保存/再開、勾配→負荷係数（grade.ts）を流用
3. 品質調整: playbackRate の許容範囲（0.5〜2.0x推奨。範囲外は
   フレーム補間なしで見た目が破綻するため、超過分はseekベースの
   コマ送り/スキップにフォールバック）

受け入れ: サンプルコースで速度連動走行が成立。停止で映像停止。

## マイルストーン3: 配信基盤とコスト設計

1. ストレージ/CDN: Cloudflare R2 + CDN（エグレス無料）を第一候補に、
   1コースあたりの容量（4K HLSで目安 2〜4GB/時間）と月額を試算
2. コースカタログAPI（一覧・メタ・署名付きURL）: 最小構成は
   静的JSON + R2、将来はSupabase等
3. 認証・課金の骨格（Stripe）: 無料コース＋サブスクの2段構成
4. 計測: 視聴ログ（どのコースが走られたか）

受け入れ: サンプルコースがCDN経由で再生でき、コスト試算表が docs にあること。

## マイルストーン4: 権利・安全対応（公開前必須）

1. 自前撮影分: 撮影地の法規（公道撮影は原則可）、ナンバープレート・
   歩行者の顔の自動ぼかし（ffmpeg + 検出モデル or 外部サービス）を
   変換パイプラインに組み込む
2. 投稿モデルへ拡張する場合: 投稿規約（権利許諾・肖像権責任・削除対応）、
   審査フロー、通報窓口。※弁護士レビューは人間側タスク
3. 利用規約・プライバシーポリシー整備

## マイルストーン5: クローズドβ

- コース3〜5本、知人ユーザー数名で検証。酔い・同期ズレ・負荷体感を
  アンケート化し、playbackRate範囲・勾配係数をチューニング
